# Toolkit plan – working rules for all contributors

Goal: turn the 16 Lean / CI / Kaizen course tools (original author **John Naska, mokka.solutions**, published with his
permission; further development **Milad Karami**) into one consistent, bug-free toolkit, organised along an improvement
process (DMAIC with a strategic context phase).

## Repository layout

| Path | Purpose |
|---|---|
| `src/tools/*.html` | **Source** of each tool (original + bug fixes). Edit tools only here. |
| `src/tools/*-en.html` | **English source** of each tool (same code, translated UI). A fix in a German tool must also be applied to its `-en` file. |
| `tools/*.html` | **Built** tools = source + shared toolkit layer (header, animated logo, PDF report, theme). Generated by `build/build.py` – do not edit by hand. |
| `build/` | Shared layer and build script. |
| `assets/` | Logo and illustrations. |
| `index.html` | Hub page (organised by process phase). |
| `kanban-regelkreislauf.html`, `kanban-control-loops.html` | Kanban tool (already reworked, DE/EN). |

## Rules for bug fixing (`src/tools/`)

1. Each tool is a single self-contained HTML file. Keep it that way (no external dependencies, must work offline via `file://`).
2. Each tool exists in German (`<id>.html`) and English (`<id>-en.html`, Kanban: `kanban-control-loops.html`). Keep both in sync: same ids, data, storage keys and logic – only the UI text differs. No Persian/Arabic characters.
3. Fix real bugs only: runtime errors, wrong calculations/logic, broken buttons, exports (Markdown/JSON/Obsidian) that crash
   or produce wrong content, state that is not saved/loaded correctly, layout breakage, accessibility basics.
   Keep fixes minimal and local; do not refactor or restyle (the shared layer handles the look).
4. Do not change ids, data structures of saved projects, localStorage keys or the export formats' structure
   (saved user projects must keep loading).
5. Keep all credits to John Naska and the source citations exactly as they are.
6. Mark each fix in the code with a short German comment `// FIX (Toolkit): …` and list all fixes in
   `src/CHANGES/<tool>.md` (what, why, how verified).
7. Verify in a real browser (headless Chrome/Playwright): page loads without console errors, all examples load, all steps
   can be navigated, `buildMarkdown()`, `buildJSON()`, `buildObsidian()` return content for every example.
8. Commit messages: plain, descriptive. **Do not add any `Co-Authored-By` trailer and no "Generated with …" lines.**

## Known observations from the baseline smoke test (2026-10-11)

- No console errors on load in any tool.
- `kano-modell.html`: has `STEPS` but no `showStep()` – check whether step navigation works through its own mechanism.
- `prozess-begehung.html`, `pdca.html`: define `EXAMPLES` but no `loadExample()` – check how examples are loaded in the UI.
- `ishikawa.html`, `prozess-begehung.html`: contain a CSP meta tag without `'unsafe-eval'` and large embedded libraries
  (draw.io viewer, bpmn-js, fonts) – leave those library blocks untouched.
